## 0. Verdict

1. **The project was one disk failure from losing five weeks.** Fixed today: history pushed and
   verified. Details in §1.
2. **The live bot contradicts four of the charter's load-bearing commitments.** It reads card
   names, sees hidden information, imitates a hand-written heuristic, and has no planner. Each one
   alone fails rank 1 as NORTH_STAR defines it (§2, A-1).
3. **It has never beaten the 100-line heuristic it imitates,** and on M21 no network's CI against
   the rig's random opponent excludes 0.5. The evaluation design overstates even that: best-of-3
   selection, unpaired seeds, draws and crashes left out of the denominator (A-2).
4. **The simulator is a simplified "batch Magic"** without priority. Commander has no
   implementation at all. Strength numbers are strength at that simplified game (A-3).
5. **The generalization claims are not evidence yet.** ZNR was used to develop the parser, the
   policy cannot represent an unseen card, and partly compiled cards are dealt as if whole (A-5).

None of this means the work was wasted. The rules engine is careful, its test discipline is
unusually honest (red-first batteries, registered fails, adversarial gates), and 428 scripted packs
pass. The problem is that the strength track ran ahead of the commitments the strength is supposed
to rest on. The cheapest correction is to stop training on the omniscient, name-reading
representation before investing more compute in it.

### A-2 Strength is below the charter's bar, and the measurement overstates it

- **It has never beaten the heuristic.** The frontier's 0.4256 [.358, .496] at n = 200
  (`reports/FRONTIER.md:5`) was the best of three seeds: the siblings scored 0.3660 and 0.3692
  (`reports/FRONTIER.md:10`; `KNOWLEDGE/2026-10-13/77-shadow1-frontier.md:5-6`). A fresh 400-game anchor gives
  **0.394 [0.347, 0.442]** (`KNOWLEDGE/NUMBERS.md:3904`). The drop was attributed to engine "era
  drift", but it is exactly what selecting the maximum of three noisy estimates predicts. This is
  the winner's curse, observed in-house. D8 ("the student must exceed the teacher",
  `docs/DECISIONS.md:127-129`) is failing.
- **It barely beats the rig's random opponent.**

  | Matchup | W-L | Win rate (decisive) |
  |---|---|---|
  | shadow M21 | 23-17 | 0.575 [0.422, 0.715] |
  | shadow ZNR | 27-13 | 0.675 [0.520, 0.799] |
  | bc10_S4 | 90-100 | 0.474 |
  | bc10_S0 | 86-102 | 0.457 |

  Sources: `reports/shadow_*_vs_random_2026-10-19.json`, `tools/eval/gameplay_eval_v5_bc10S4.json`, `gameplay_probe_bc10S0.json`. The frontier itself was never measured against random.
- **The denominator hides draws and crashes.** Win rate is `wins / (wins + losses)`
  (`gameplay_eval_v2.py:849-861`). Converting losses into draws therefore raises it, and model-lane
  crashes are 9–12 per 200 games in the files above.
- **The comparisons are unpaired.**
  - Checkpoints are scored on rotated or overlapping seed ranges.
  - The three 35M runs shared their seeds, so their "±0.004 spread" is shared deal noise.
  - A seed-base reuse produced a +0.400 divergence (`KNOWLEDGE/2026-10-20/134-rl-pilot-design-draft.md:10`).
  - Result JSONs record neither the engine revision nor the set.
- **No external opponent has ever been played:** no Forge, XMage, human or LLM. The RL verdict is
  "mirror vs the frozen pre-RL clone" (`/134:6`). That is METRICS ST-5's "ladder made of itself".

### A-3 The simulated game is "batch Magic"

- **Priority and responses.**
  - "Batch style, no priority simulation" (`MTG_bot/core/executor/games.py:42`).
  - One act batch per turn in the first main phase (`games.py:638-686`).
  - A single, counter-only response round (`core/executor/stack.py:8-21,838-864`).
  - Combat "runs UNINTERRUPTED" (`core/executor/__init__.py:1472`).
  - Spells with more than one target slot are skipped and counted (`games.py:562-570`).
- **Rules deviations.** Mana is never emptied between steps; the harness docstring states it
  (`games.py:55-56`), and CR 500.4 requires mana to empty at the end of each step. The ask channel
  can only ask the effect's controller (gap L-27, `core/compiler/compiler.py:1190-1203`), so "an
  opponent chooses" effects are silenced per card.
- **Commander has no implementation.** There are 2 seats at 20 life (`games.py:1077`) and 60-card
  decks (`games.py:129-134`); the command zone is a constant (`core/state.py:40,97`). Every live
  game is 1v1 Limited-style.

A policy can only be as good at Magic as the game it trains on. Instant-speed interaction, holding
up mana and combat tricks are where much of real Magic's skill lives, and none of them exist yet.

### A-4 Goodhart in the live meters

- **Stalling pays under the RL reward.** `REWARD = {"win": 1.0, "loss": -1.0, "draw": 0.0,
  "crash": -1.0}` (`tools/training/train_rl_v1.py:53`). The turn cap (`games.py:1405-1407`) and the
  stall rule (`games.py:1370-1379`) both yield draws, so a policy that loses about 60% of games
  gains by stalling. D10 rules exactly this out (`docs/DECISIONS.md:151-158`), but nothing in the
  live code enforces it.
- **MCTS values reward breaking the game.** A crashed rollout scores 0.5, and an unfinished one
  scores `0.5 + clamp(life_diff)/40` (`tools/search/mcts.py:121-131`). A losing search therefore
  prefers lines that crash the engine or lead on life.
- **The puzzle meter is contaminated.** 141 of its 199 items are the checkpoints' own training
  rows (`KNOWLEDGE/2026-10-15/86-generalization-meter.md:17-25`). A collapsed checkpoint scored
  win rate 0.0 with accuracy 0.766 (`FRONTIER.md:15`). It was correctly demoted to report-only,
  the one place METRICS §17 pairing was visibly applied.
- **Degenerate play goes unflagged.** The frontier answers ATTACK on 100% of 2,257 attack asks
  and accepts 100% of 539 may-asks; the heuristic declines 17.9% of its attacks
  (`tools/eval/gameplay_anchor_bsh_cur_engine.json`, `policy_asks`/`baseline_asks`). No report
  flags it.
- **Coverage is parse coverage.** PC-1/PC-2 count sentences parsed, not meaning preserved:
  clauses dropped by miscompiles still count as covered (`KNOWLEDGE/2026-10-19/128-...:68-73`).
- **Fuzz used the wrong policy.** It ran RandomPolicy and reported 0 crashes in 4000 games. Model
  play crashes the engine in about 5% of games (A-2).
- **The RL update is a no-op by construction.** One `SGD.step` per collected batch
  (`train_rl_v1.py:253-255`), lr 1e-5 and clip 1.0 (`:131-132`), on a 1000-game iteration-1
  (`tools/ops/rl_pilot_phases.sh:31`). No weight can move more than 1e-5 per iteration, and the
  dry run's KL to the anchor was about 1e-9.

### A-5 Generalization claims are not yet evidence

- **ZNR is not unseen.** The compiler was iterated on ZNR's unparsed register over many rounds.
  The only honest zero-code-change number is the first touch: **0.142 compile / 0.281 sentence
  coverage** (`KNOWLEDGE/2026-10-18/93-znr-first-census.md:1`).
- **The parser is a sentence-template library**, not a compositional parser. It has 384 regex
  templates and 65 exact-sentence templates with per-card builders (e.g. `_build_goremand`,
  `core/compiler/templates_b2a.py:2685-2689`), matched by `pattern.fullmatch(sentence)`
  (`core/compiler/templates.py:162-176`). A new card is free only if every sentence already has a
  template. **The parser, not only the policy, is the tied-rank-1 bottleneck.** There is also a
  per-card override table (`PICK_ASK_FORCE_SILENT`, `compiler.py:1198`).
- **Partly blank cards are dealt.** `engine_supported` checks the verbs and shapes of the atoms
  that *did* compile (`compiler.py:2259-2302`). A sentence that failed to compile produces no atom,
  so it cannot make a card unsupported. 267 ZNR cards are deckable while 108 compile fully, which
  contradicts "A card that does not compile cleanly is not in the enabled pool. No silent
  degradation." (`docs/DESIGN_CARD_POOL.md:219`).
- **"ZERO generalization gap"** (`KNOWLEDGE/2026-10-19/123-...:1`) rests on 40 games per cell, a
  policy that cannot see unseen card identities, and an opponent that ignores identity. Parity
  there says nothing about compositional transfer.
- **The ZNR gold packs are thin.** There are 10 items over 6 cards, with agent-authored labels; one
  draft contained a fabricated card ("Roil", `/128:75`).
- **Live games carry no oracle text.** `identity_of` copies no `oracle_text` and stamps
  `set_code="M21"` on every card, ZNR included (`games.py:326-348`).

## 3. Recommendations

Ordered within each group by value per unit of work. "Proof" is the test or number that shows
the change worked.

### 3.1 Validity before strength (do these before any more training compute)

1. **Train and evaluate only on a per-seat view.** The benchmark's `MTG_bot/bench/view.py` is
   that view: own hand, counts for hidden zones, opaque object ids, oracle text. It ships with a
   metamorphic hidden-information test. *Proof:* replace the opponent's hidden cards with
   sentinels and the encoded observation is byte-identical. Do not resume the RL pilot on the
   omniscient net. RL would sharpen exactly the dependence on hidden information that the owner
   ruled out.
2. **Score cap and stall draws as losses for both seats in the training reward,** and report them
   separately in evaluation. That is D10 applied to the turn cap and stall rule. *Proof:* a
   "stall when behind" policy scores strictly worse than playing on.
3. **Determinize hidden state in search.** Sample the opponent's hand and library order from the
   public information set instead of forking the real game. Value crashed rollouts as losses for
   the searcher, not 0.5.
4. **Route every engine ask by the deciding seat.** The `asking_seat` hook added to
   `DecisionStream` today makes this exact for both the bench and the rig. Fix the rig's
   active-player fallback and re-collect any data gathered with it.
5. **Fix or register the two rules deviations:** the mana pool must empty per step (CR 500.4), and
   trigger quarantine must be replaced by the loop-shortcut design in `DESIGN_INFINITIES.md`.
6. **Make priority the next engine rung**, before Commander. Without it the game being learned is
   not Magic.

### 3.2 Generalization (tied rank 1)

1. **The policy reads the IR, never the name.** Serialize the ability tree (verbs, selectors,
   quantities, filters, numeric buckets) as the card tokenizer, as `DESIGN_ATOM_ONTOLOGY.md` §8
   already plans. Keep names only as opaque per-game pointers.
   *Gates:*
   - **name-permutation invariance:** consistently renaming every card leaves the action
     distribution unchanged;
   - **IR-twin identity:** cards with identical IR get identical embeddings. The existing twins
     census (`reports/r4_twins_census.json`) is a free test set.
2. **Measure the parser the way the charter states the goal.** The tied-rank-1 number is
   *first-touch* coverage on a new set at a frozen compiler commit, plus "templates added per 100
   new cards" (code changes per card, literally).
   - Seal the next set: no grammar work against it until first touch is recorded.
   - For ZNR, split cards into a dev half (grammar may iterate) and a sealed test half.
   - Then compare the owner's 2026-09-16 per-card LLM translator, grammar-constrained into the IR
     and verified by round trip, against the template library on the same sealed set.
3. **Deal only cards that compiled completely.** Alternatively, tag per-card fidelity and exclude
   partial cards from every evaluation pool. Either way, enforce `DESIGN_CARD_POOL.md:219` in
   `engine_supported`.
4. **Use compositional splits, not set splits.**
   - *Leave-one-mechanic-out.*
   - *Compound-divergence* splits (Keysers et al. 2020): atoms all seen, combinations unseen.
   - *Synthetic cards* composed from practised atoms, rendered to text and round-tripped through
     the compiler. These test the compiler and the policy at the same time and cannot be
     contaminated.
5. **Metamorphic card tests.** Change one number in a card's text ("deals 3" → "deals 4") and the
   engine's outcome must change by exactly that amount. Swap the colors consistently across a
   whole game and the outcome must be unchanged. These catch compiler bugs that parse coverage
   cannot see.
6. **Measure competence per card, not parity.** Use puzzles with oracle solutions per mechanic:
   did the policy use the card when using it was correct? Win-rate parity against an
   identity-blind heuristic cannot detect a policy that ignores the card.
7. **Diverse opponents and exploitability.** Use the heuristic, uniform random, do-nothing, past
   checkpoints and LLM seats, and train a cheap best response against the frozen policy. An
   always-attack policy is exploitable, and exploitability measures that directly.

### 3.3 Tests

1. **One contract, one baseline:** command, date, commit and numbers in one place (CLAUDE.md).
   Done 2026-10-24 (B0).
2. **The 428 packs as pytest cases** (1.3 s). Done 2026-10-24.
3. **Red-first batteries behind a marker** (`-m red_first`), so the default run stays meaningful
   and nothing is lost. **A strict known-failure registry for the legacy tests.** Both done
   2026-10-24.
4. **Fuzz with the model, not only RandomPolicy.** Model play crashes the engine in about 5% of
   games while the random fuzz said 0/4000. Add a frontier-policy lane and an adversarial lane that
   seeks long trigger chains. Run invariant checks after every action:
   - every card in exactly one zone;
   - life and counters well typed;
   - the state-based-action fixpoint idempotent;
   - the stack consistent;
   - replays byte-identical.
5. **An independent rules oracle.** Today the packs prove the engine agrees with labels its own
   authors wrote. Add a second oracle: label adjudication by a different model family or a human,
   recorded per pack (`adjudicated_by`), and, worth costing, differential runs of the packs in
   Forge's puzzle format.
6. **Checkpoint-dependent tests skip loudly when the file is absent** and verify the SHA-256 when
   present. The skip half is done 2026-10-24.
7. **Eval outputs never default to a tracked path.** `gameplay_eval_v2.py`'s default `--out` is the
   tracked record (the PITFALL that bit again this month). Default to a timestamped file.

### 3.4 Evaluation protocol

1. **A pre-registration file per run:** opponents, n, seeds, metric, decision rule. The results
   are appended to it, not written elsewhere.
2. **Duplicate format:** the same deal is played twice with seats swapped, and the pair is the
   unit. Use a paired bootstrap over deals, and an SPRT for "is A stronger than B" so a run stops
   as soon as the evidence suffices. All of these are in `MTG_bot/bench/`.
3. **Report every seed.** A best-of-k pick must be re-measured on fresh seeds before it is quoted.
4. **Stamp every result** with the engine revision, set code and pool hash.
5. **Floors in every table:** do-nothing and uniform-random-legal, played on the same deals.
6. **The first external opponents:** LLM seats through the benchmark harness, then Forge/XMage AI
   if a bridge is affordable.

### 3.5 Process

1. **Run the adversarial gate on a different model family** from the authors. Correlated errors
   are the failure mode of a monoculture, and this review is one data point for the value of an
   outside reader.
2. **One git worktree per agent session.** A shared index on `main` has already cost commits.
3. **A ≤ 50 KB session digest** (current numbers, open traps, active rung), regenerated per
   session, replacing the 660 KB reading list. Split `NUMBERS.md` by month.
4. **One ID namespace per document type.** Mark METRICS.md as legacy-engine until it is
   re-derived; refresh DECISIONS.md with what has actually been decided since 09-10.
